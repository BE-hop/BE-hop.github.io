## 基线与备份

- 基线：`b1e07d8b`，正式域名为 www.behop.cn。原图、本地未同步工作区快照及SHA256清单保存在仓库外，不进入部署。
- 主目录旧master提交保留在 `codex/local-main-before-performance-20261016`；未发布编辑器/AI情报等功能保存为具名stash `behop-local-drafts-before-performance-alignment-20261016`。不要直接将整个stash应用到新master：先按备份中的alignment-classification.json识别已发布/仅本地/仅本地新文件，再按功能移植。
- 主目录中61项与线上相同、17项存在本地差异、6项仅本地存在。代码、内部说明、测试和原始职业材料不因本轮性能优化额外公开。

## 性能策略

- 188张源媒体约150.58MiB；强压缩后约30.09MiB。构建额外生成约21.7MiB响应式WebP，整体图像产物约51.8MiB，较原始媒体减少约65.6%。SVG与动画保留性质。
- 英文字体9个拉丁子集共173252字节，自托管并保留OFL许可。未引入中文字体包。
- 全站HTML/CSS由构建钩子生成响应式图片与小封面；未引用源图不预载。完整图面不裁切；放大图只在放大镜交互后请求。
- 离线缓存仅承诺已访问资源：图片最多60MiB/100项，其余页面/资源最多120项。在线HTML优先网络，失败后才回退缓存；论坛JSON优先网络。
- 正常升级不强制刷新。页尾可检查更新、手动切换新版本、修复本站缓存。修复不删除localStorage语言设置。

## 复测方法与限制

`scripts/performance-preview.py --site <构建目录> --port <端口>`模拟本地聚合1.6Mbps带宽和每请求150ms延迟；响应禁用浏览器HTTP缓存，以390px视口测试首访。该实验不模拟CPU限速、DNS、TLS和各地区链路，不能冒充所有访客的真实用户指标。

浏览器注入仅用于此本地实验的PerformanceObserver，采集LCP、CLS、长任务、请求量和传输字节；不会部署到正式站点。重复测量记录放在仓库外验收报告。以实际数据注明未达目标项，不虚报跨电脑验证。

## 发布规则

GitHub Pages Source设为GitHub Actions。仅`Deploy Jekyll site to Pages`负责发布：master推送、手动触发及成功的论坛同步均进入该流程；同一pages并发组顺序执行。论坛同步自身仍只更新审核快照。

构建需要Python/Pillow和Ruby，入口为scripts/jekyll-with-assets.rb；不能只运行裸Jekyll并跳过图片/版本管线。release.json记录实际构建提交与资源版本。以线上release.json、页面meta和本地git HEAD交叉验证。博客时区Asia/Shanghai，10/15旧地址跳转10/16固定地址。

## 内容可见性

原有隐藏AI工具/图库状态不变。列表隐藏不代表私密访问；本轮不自动公开或删除它们。编辑器草稿及手工AI情报导入功能不随性能修复发布。

旧缓存迁移不在安装时强制skipWaiting；新页面检测到waiting worker后提示用户切换，避免旧页面填写中突然刷新。首访离线预热在页面资源加载完成后的空闲时进行。

## 移动端首访对比（本地固定限速）

390px视口、聚合1.6Mbps、每请求150ms、HTTP缓存禁用。作品集优化前3次LCP为11.044/11.084/11.040秒，约2.96MB、15–16请求；优化后3次为2.144/2.212/2.084秒，约0.368MB、21请求，CLS均为0，未观测到长任务。离线访问已访问Works页面的真实浏览器验证通过。真实两台电脑与地区网络尚不能代替用户实机确认。

响应式图片用data-original-src保持编辑器源字段映射，替换草稿清除旧srcset；工程验证为完整npm run check。

## 2026-10-16 真实网络资源下载故障修复

用户实际Chrome出现CSS缺失与展板断图。线上HTML、CSS、WebP请求均可返回200，但本机curl捕获CSS只传9565/12303字节后超时；107354字节WebP在一次HTTP/2请求中仅传28713字节后15秒超时，同次HTTP/1.1传完。此证据不能单独归因于Cloudflare、代理或运营商之一，也不是路由404；未更改DNS或平台设置。

关键入口构建时内联样式及有序脚本，作品集首图内置480px预览，高清加载成功后替换，12秒失败显示重试。Works/作品集/论坛HTML gzip约35/126/51KB。故障注入服务器对/css、/js、/media、/img统一返回503：作品集封面与480px首图仍显示，重试按钮出现；论坛列表和导航仍初始化。此方案降低分散请求失败的影响，不承诺底层HTML链路永不超时。

## 凌晨架构对照与修正（取代上面的临时内联补丁）

对照b1e07d8b：保留轻量Jekyll HTML和独立CSS/JS；撤回整页内联与Base64展板，保留压缩资源及作品内容。CSS/JS使用各文件内容哈希，论坛快照同步不再导致所有前端资源重新下载。SW恢复缓存与网络竞争的思路：快网新内容优先，慢网1秒使用已访问页面；网络正文完整性与8秒超时纳入处理。网络返回200但正文停滞时不再把半页HTML交给浏览器。离线/超时兜底是无需独立资源的轻量重试页。

新增回归：在线请求不返回响应头、200响应头后正文不结束、文章/论坛内容更新不使未变化CSS版本失效，以及CSS修改会改变自身版本。未操作0dcloud或系统代理。

后续交付在轻量HTML结构内按内容哈希合并独立CSS与顺序脚本，各一份缓存文件，降低冷连接并发。增加一次性头部worker恢复，避免旧worker的升级依赖页面末尾脚本；仅未完成且无表单的文档允许一次恢复重载，之后升级仍手动。
